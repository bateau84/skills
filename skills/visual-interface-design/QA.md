# visual-interface-design Quality Assurance

Adversarial validation for any agent. Assume competent production and normal review; attack residual false confidence without inventing new requirements.

## QA criteria

Critic probes information under degraded perception: grayscale/no color, high zoom, narrow viewport, dense/error states, focus vs hover, and reduced motion. Ask whether severity/action/status could be misread and whether token/system exceptions accumulate into visual drift.

Challenge apparent polish that depends on ideal placeholder content, one photogenic state, or a still image used to claim interaction quality. Also challenge mechanical audits that reject a useful optical correction, tabular numerals, or accepted expressive treatment solely because it violates a generic recipe. Compare the actual result with accepted intent and constraints.

Block when visual choices hide a required state/action, materially misrepresent severity/status, make an accepted task inaccessible, contradict accepted behavioral design, or fragment the design system enough to create inconsistent semantics.

Aesthetic preference alone is not a gate defect. A concrete departure from accepted visual intent can be drift; a new preferred style is not. Do not require every decorative color to carry information, turn novelty into a quota, or treat an expert aesthetic judgment as measured user preference.

## QA depth

Increase depth with state density, data visualization, themes/breakpoints, accessibility consequence, novel visual language, design-system reach, and importance of visual status/severity cues.
