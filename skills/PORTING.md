# Skill Portability and Provenance

This library was copied from Loom. Earlier source lineage includes `nrkno/mats-opencode-setup/skills`; Go skills retain their individual `samber/cc-skills-golang` attribution and license metadata.

## Portable contract

- Skills supply reusable methodology, not runtime permissions or orchestration.
- Any agent may perform the practice, review, or adversarial-validation activity described by a file.
- No fixed role hierarchy, plugin, report schema, semantic-memory service, or evaluation harness is required.
- User instructions, repository conventions, and host permissions govern execution.
- Artifact templates, identifiers, and example paths are adaptable to the project.
- External tools remain explicit dependencies of the technical integrations that actually use them.

## Adaptations

Framework-specific tool calls and role-exclusive operations have been replaced with ordinary file/tool workflows. Report creation and retention preserve evidence and provenance without requiring an indexing service. Learning records use a project-selected durable store, with semantic search optional. Git guidance uses standard commands and preserves repository hooks.

`loom-learning` is now `learning`. Optional `ASSESSMENT.md` and `QA.md` files retain distinct conformance and residual-confidence methods without requiring dedicated reviewer or critic agents.

## Preserved methodology

The library retains product and behavioral specification, architecture, delivery planning, acceptance, design, accessibility, documentation, Git, Go, Python, JavaScript/TypeScript, observability, infrastructure, Terraform, MCP construction, TDD, and performance guidance.

Portable authoring principles retain discovery/retrieval quality, progressive disclosure, risk-matched specificity, composability, durable knowledge, observed-failure grounding, source curation, and realistic behavioral evaluation.

## Future ports

Copy or adapt reusable domain method. Rewrite useful material entangled with a particular runtime. Keep licenses and meaningful source attribution. Defer niche integrations until needed. Do not import missing agent prompts, private plugins, repository-internal documents, or obsolete workflow mechanics as dependencies.
