# Anchor Authoring Quality Assurance

Adversarially challenge a seemingly complete and accepted Anchor. This is a substantive false-confidence check, distinct from ordinary assessment or OKF structural checks.

## QA criteria

- **Plausible-wrong implementation:** Construct an implementation that obeys the Anchor literally but defeats the user's goal. Identify the missing outcome boundary if one exists.
- **Parallel divergence:** Imagine two competent independent agents taking contradictory interpretations of ordering, authority, lifecycle, default behavior or failure recovery. Is shared meaning settled or explicitly unresolved?
- **False authority:** Look for agent recommendations, implementation accidents, examples, and weak user language treated as accepted mandates.
- **Hidden contradiction:** Compare the Anchor's meaning with earlier accepted intent and exclusions. Has scope silently expanded or an existing guarantee weakened?
- **Acceptance laundering:** Challenge claims of user acceptance unsupported by an actual decision or acknowledgement.
- **Missing conversation:** Remove the originating chat. Can a new agent still distinguish decisions, proposals, constraints and open questions?
- **Premature doctrine:** Check that first principles were not invented from one Anchor or imposed as policy without later cross-project evidence and necessary user acceptance.
- **Unnecessary ceremony:** Challenge redundant questioning, excessive detail, and requirements for documents or approvals that do not change the intended outcome.

## Result

Report residual risks with concrete examples and cite their source. Do not invent a new product decision, block unrelated routine work, or substitute format-validation success for semantic QA.
