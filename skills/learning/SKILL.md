# Learning

Learning preserves experience; it does not create authority.

## Record

Record a lesson only when it is both reusable and supported by observed evidence. Prefer lessons about failure causes, successful engineering patterns, diagnostic traps, review findings, or operational behavior that are likely to recur.

1. Keep current accepted authority and current evidence primary.
2. Write the lesson in the project's chosen durable notes or memory store. Include context, the observed mechanism, supporting evidence/provenance, applicability limits, date, and confidence. No memory service is required.
3. New heuristics are provisional unless independent support justifies stronger status.
4. Optionally index the record for recall if a search/memory integration is available. Index failure does not invalidate the source record; retain a stable path or identifier to it.
5. Never store an unconfirmed theory as established learning.
6. When recorded episodes justify a general rule, document it as a provisional heuristic. Strengthen confidence only with independent support and review appropriate to the consequence.

## Recall and correction

Semantic recall is advisory. Read the original source record and check applicability and freshness before relying on remembered material.

When direct evidence contradicts recalled learning:
- treat it as stale for the current decision and surface the contradiction;
- update its status through the project's normal editing/review process, preserving the old evidence and reason for correction. No particular agent role owns this operation.

If a heuristic loses enough independent support, demote its confidence rather than pretending it remains validated; loss of support alone does not prove the whole heuristic false.

Memory and heuristics never silently override current accepted authority or direct current evidence.
