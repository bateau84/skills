# Work Handoff — Reviewer Assessment

Review the **handoff artifact** against accepted intent and available current evidence. A clear document can still assign the wrong work.

## Review criteria

1. **Decision fidelity:** Latest accepted intent survives; earlier rejected suggestions, speculative examples and agent proposals are not promoted to requirements or silently dropped when they materially constrain the work.
2. **Coherent work boundary:** The handoff has a meaningful owner/responsibility and deliverable; separate unrelated outcomes are not buried together, and the same cross-boundary obligation is not abandoned by splitting.
3. **Cold-start completeness:** Without the source chat, a recipient can understand the problem, outcome, relevant context, accepted limits, evidence, prerequisites and success condition.
4. **Grounding:** Current-state claims, code/repository paths, proposed mechanisms, root causes and related issue/PR references are verified when available or clearly marked uncertain.
5. **Readiness honesty:** Implementation, investigation and decision work are distinguished; unresolved user-owned choices remain visible rather than becoming implementation criteria.
6. **Acceptance quality:** Conditions are observable or the investigation/decision deliverable is bounded. Regression, compatibility and integration expectations appear when material.
7. **Contract integrity:** In cross-component work, source and target, normative levels, interface status and observable seam acceptance are clear. A suggested endpoint does not become required merely through restatement.
8. **Destination neutrality:** The artifact does not depend on Markdown checkboxes, GitHub labels, an agent scheduler, private chat links, or a specific host to remain meaningful.
9. **Proportionate detail and safety:** The document preserves necessary context without dumping transcripts, guessed implementation steps, private data or secrets.

## Evidence limits

A self-contained handoff makes a task intelligible; it does not prove the work is correct, approved for execution, or already implemented. Self-review may catch issues but is not independent merely because this file was read.
