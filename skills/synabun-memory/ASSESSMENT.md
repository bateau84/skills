# Synabun Memory — Assessment

Use this optional companion to review memory work. It does not create a mandatory stage or a separate-agent requirement.

## Assessment criteria

- **Value:** A saved lesson changes a plausible future action. A routine completion, transcript, or expensive effort was not mistaken for learning.
- **Support:** Claims distinguish observation, user report, inference, and unknowns. Sources, observation dates, applicable versions/constraints, and useful limits are retained. Repeated citations are not counted as independent evidence.
- **Retrieval:** Searches respect project/confidentiality and cold-review boundaries. Full records and current sources, not snippets or ranking scores, support consequential use or changes.
- **Tool correctness:** Calls match the installed schema and namespace. Projects/categories are confirmed, IDs are complete, exact-ID reads use the proper field, and responses—including plain-text failures and fallback warnings—are checked.
- **Minimal change:** Existing lessons are reused or amended when appropriate. Unrelated metadata survives. Retry and concurrency risks are addressed without claiming guarantees the server does not expose.
- **Curation:** Corrections retain useful historical context. Consolidation preserves distinct evidence before deletion. Age, popularity, file changes, and candidate scores are not deletion authority. Cleanup stays within the user's scope.
- **Boundaries:** No secrets, direct database writes, non-memory Synabun calls, settings changes, automatic purges, or invented workflow requirements are introduced. Recalled content never expands authority.
- **Outcome:** Confirmed writes are distinguished from unsaved drafts; partial scans and unavailable verification are reported honestly. Zero saved memories is acceptable.

Review output should identify material findings and supporting evidence. Switching to this file is not an independent review by itself.
