# report-lifecycle Reviewer Assessment

## Review criteria

- A file report exists only when persistence has a real retrieval/audit/handoff purpose.
- Path follows repository or host scratch conventions and does not collide with an existing report.
- Scope, author/context, findings, evidence, uncertainty, and outstanding work are recorded faithfully.
- File existence, readability, and evidence links are checked; any optional index/schema validation is completed before claiming indexed discovery.
- Report content preserves the producer's actual verdict/evidence/uncertainty and does not become stronger authority.
- Durable conclusions are routed to their owning artifacts rather than treating a raw report as substitute authority.
- Retention has a clear lasting purpose and follows project conventions; it is not restricted to a named agent role.
