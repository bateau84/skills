# Work Decomposition — Residual-Confidence QA

Adversarial validation for any agent. Assume competent production and conformance review; attack residual false confidence without inventing new requirements.

## QA criteria

- Trace one shared guarantee through all groups despite their individually complete-looking ownership records. Could both sides implement incompatible meanings while each local proof passes?
- Simulate one late/failed group or a contract revision. Does downstream work merely wait, or silently become invalid? Probe whether a provisional stub is later mistaken for final integration.
- Construct a legal interleaving: two groups read the same old configuration, edit different concerns, and publish in turn; or run independent tests against one database. Could writes be lost or proof depend on another group's state even if file mutations are locked?
- Try merging adjacent groups and splitting mixed ones. Does the chosen grouping conceal an irreversible rollout, duplicated policy, incoherent rollback, or a real ownership seam despite a clean dependency graph?
- Challenge the change-surface evidence with an independent consumer or generated source missed by all groups. Trace an accepted scenario that uses that consumer and see whether the assembled proof would notice.
- Follow final composition proof back to its prerequisites: are all real implementations present, or does each group assume the other removed a mock/fallback? Look for common local-test assumptions that make every group green while the product is broken.

Tie findings to accepted obligations and concrete counterexamples. Do not introduce new product scope or forbid useful parallel work merely because a hypothetical risk can be named.

## QA depth

Increase QA depth where a shared wrong assumption could survive both competent production and normal review.
